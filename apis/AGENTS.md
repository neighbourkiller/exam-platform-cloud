# API Contract Guidelines

本文件适用于 `apis/` 下的跨服务契约模块，并与仓库根 `AGENTS.md` 共同生效。

## 模块职责

- `apis/` 只存放跨服务 DTO、枚举和 Feign 契约，不放业务实现、持久化逻辑或服务专属配置。
- API 模块不得依赖 `services/`，也不得暴露服务内部实体、数据库结构或实现细节。
- 只有确实跨越服务边界的数据结构才进入 `apis/`；服务内部 DTO 留在所属服务。

## 契约演进

- 契约应保持稳定、明确且可序列化；字段命名、空值语义、枚举值和时间格式不得含糊。
- 优先采用向后兼容的增量演进。删除、改名、改类型或改变字段语义前，必须确认迁移窗口和发布顺序。
- 修改 Feign 方法时检查路径、HTTP 方法、参数绑定、认证要求、返回类型和异常映射。
- 修改 DTO、枚举或 Feign 契约时，定位全部调用方和实现方；若字段同时用于事件载荷，还要检查生产者、消费者及历史消息反序列化。

## 验证

- 多代理协作时，同一公共契约的写入由主代理统一协调，独立调查与验证可并行；单代理执行无需额外协调步骤。
- 至少编译或测试 API 模块及全部受影响服务；最终说明兼容性结论、发布顺序和未覆盖的调用方。
