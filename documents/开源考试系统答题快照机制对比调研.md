# 开源考试系统答题快照机制对比调研

> 调研日期:2026-09-06。星标数据为当日通过 GitHub / Gitee REST API 实时查询的结果。
> 调研方式:逐仓库浅克隆(`--depth 1`)后 grep / 阅读源码核实,所有结论均附文件路径证据,非文档转述。

## 一、调研背景

EkuExam Cloud 的 exam-runtime-service 实现了"定时答题快照 + 客户端租约 + 服务端超时接管"的交卷可靠性机制。为评估该设计在同类开源考试系统中处于什么水平、有哪些可借鉴的实现,本文对 10 个高星 / 热门开源考试平台逐一核实其"考试中存储答题快照"的能力与实现机制。

## 三、结论速览

| 项目 | 考试中答题快照 | 触发方式 | 存储介质 | 断点续答 |
|------|----------------|----------|----------|----------|
| Moodle | ✅ 服务端 | 定时(默认 60s)+ 答案变化驱动 | 数据库 question_attempts | ✅ 跨会话,从 DB 恢复 |
| 硕果云 sg-exam | ✅ 服务端 | 切题动作驱动 | MySQL exam_answer(唯一索引 upsert) | ✅ 复用未提交记录 |
| 云帆考试 yfexam | ✅ 服务端 | 切题动作驱动 | MySQL paper_qu / paper_qu_answer | ✅ 复用进行中试卷 |
| online-exam-system | ✅ 服务端 | 每题作答即提交 | MySQL exam_qu_answer(按用户 upsert) | ✅ 取题接口回填已答 |
| ExamStack | ⚠️ 仅浏览器端 | 每 60s 定时 | localStorage 整卷 JSON | ⚠️ 仅同浏览器刷新恢复 |
| java-exam | ⚠️ 仅会话级 | 整卷表单提交 | 服务端 HttpSession | ⚠️ 同会话内续答 |
| 学之思 xzs | ❌ 无 | — | 组件内存 | ❌ 刷新即丢 |
| SpringBoot-Vue-OnlineExam | ❌ 无 | — | 组件内存(交卷只传总分) | ❌ |
| spring-boot-online-exam | ❌ 无 | — | 组件内存 | ❌ |
| roncoo-education | — | 开源版不含考试模块(题库/考试在商业版) | — | — |

**总结:服务端快照在开源考试系统中是少数派(4/10),其中只有 Moodle 采用定时自动保存;中文生态主流是"切题动作驱动逐题保存";定时快照 + 租约 + 超时接管的组合没有任何开源项目实现。**

## 四、详细机制与证据

### 4.1 有服务端快照的项目

#### 1. Moodle —— 定时自动保存(最完整的参考实现)

- **触发**:quiz 模块内置 autosave(YUI 模块)监听答题表单变化(含 TinyMCE 富文本、隐藏输入域),变化后延迟触发 AJAX 保存;保存周期由站点设置 `quiz/autosaveperiod` 控制,**默认 60 秒**。
- **存储**:请求发到 `mod/quiz/autosave.ajax.php`,服务端调用 `$attemptobj->process_auto_save($timenow)`,把每题响应写入 **question_attempts 表**(question usage 持久化 responsesummary),attempt 保持 "inprogress" 状态;触发 `attempt_autosaved` 事件。
- **恢复**:刷新或断线后重进考试页,直接从 question usage 恢复全部已保存答案,可跨会话、跨设备。
- **证据**:
  - `public/mod/quiz/yui/src/autosave/js/autosave.js`(监听与延迟逻辑)
  - `public/mod/quiz/autosave.ajax.php:61`(`$attemptobj->process_auto_save($timenow);`)
  - `public/mod/quiz/settings.php:92-93`(`admin_setting_configduration('quiz/autosaveperiod', ..., 60, 1)`)

#### 2. 硕果云 sg-exam —— 切题动作驱动 + 唯一索引幂等 upsert

- **触发**:不用定时器。上一题 / 下一题 / 答题卡跳题时调用 `POST /v1/answer/saveAndNext`,一个请求同时完成"保存当前题 + 返回下一题";移动端 `setInterval(1000ms)` 仅刷新已用时长显示,不保存答案。
- **存储**:纯 MySQL。服务端按 **(exam_record_id, subject_id) 唯一索引** upsert 到 `exam_answer` 表(先查后 update/insert,索引兜底);考试记录表 `exam_examination_record.submit_status` 标识未提交/已提交。
- **恢复**:`POST /v1/examRecord/start` 查用户最近一条考试记录,`submitStatus == 0`(未提交)则复用该记录返回考试信息 + 答题卡 + 题目,继续作答;已存答案按 recordId + subjectId 回填。
- **不足**:无定时快照(两次切题之间崩溃会丢最近作答);前端 `saving` 标志位在 `finally` 中同步复位,并发守卫较弱;无失败重试队列。
- **证据**:
  - `sg-exam-service/src/main/java/com/github/tangyi/exam/controller/AnswerController.java`(`saveAndNext` / `submit` 分离)
  - `sg-exam-service/src/main/java/com/github/tangyi/exam/service/answer/AnswerService.java:211-231`(upsert)
  - `config-repo/mysql/init.sql:8-31`(`UNIQUE KEY idx_record_sub_id (exam_record_id, subject_id)`)
  - `sg-exam-service/src/main/java/com/github/tangyi/exam/service/exam/ExaminationActionService.java:98-109`(未提交记录复用)
  - `frontend/sg-exam-web/src/views/exam/startExamA.vue:209-222`(saveAndGetNext)

#### 3. 云帆考试 yfexam —— 切题逐题保存(与 sg-exam 同类)

- **触发**:答题卡跳题(`@click="handSave(item)"`)、上一题 / 下一题时调用 `handSave()` → `POST /exam/api/paper/paper/fill-answer`;无定时器、无浏览器存储。
- **存储**:MySQL `paper_qu`(每题一行,含 answered / 正确性)+ `paper_qu_answer`,**逐题即时判对错**;`Paper.state` 区分考试中 / 已交卷。
- **恢复**:生成试卷时若已存在进行中的记录则复用(create-paper 查重),继续作答。
- **证据**:
  - `exam-api/src/main/java/com/yf/exam/modules/paper/service/impl/PaperServiceImpl.java:416`(fillAnswer)
  - `exam-api/src/main/java/com/yf/exam/modules/paper/entity/Paper.java:106`(state)
  - `exam-vue/src/views/paper/exam/exam.vue:259`(handSave,答题卡与切题均触发)

#### 4. online-exam-system —— 每题作答即提交

- **触发**:每题作答后立即 `POST /api/exams/full-answer`,前端展示"正在保存答案..."loading;另有 `ExamTimer` 组件 `setInterval` 倒计时,到点 emit `timeout` 自动交卷。
- **存储**:服务端按 **(examId, questionId, userId)** 查重后 upsert 到 `exam_qu_answer` 表(`updateAnswerIfExists` / `insertNewAnswer`)。
- **恢复**:取题接口 `GET /api/exams/question/single` 查询该用户已存答案回填到 VO,刷新 / 重进即可续答;前端 sessionStorage 仅存"该题已保存"标记(答题卡状态),答案本体在 DB。
- **证据**:
  - `ExamServiceImpl.addAnswer`(upsert 分支)、`ExamServiceImpl.getQuestionSingle`(回填已答,约 405-458 行)
  - `ExamController.java`(`/full-answer`、`/hand-exam/{examId}`)
  - 前端 `online-exam-system-frontend` 仓库 `src/views/exam/index.vue:547,683`(fillAnswer 调用与 sessionStorage 标记)

### 4.2 有限快照(浏览器 / 会话级)的项目

#### 5. ExamStack —— localStorage 整卷快照

- **机制**:考试中服务端**不保存**任何答案。前端倒计时每 60 秒(`timestamp % 60 == 0`)把整卷答题卡 JSON(全部答案、examHistroyId、examId、已耗时)写入 `localStorage.answerSheet`;页面加载时 `loadAnswerSheet()` 校验 examHistroyId 匹配后回填表单。
- **交卷**:才 POST `student/exam-submit`,答案以 JSON 投递到 **RabbitMQ 队列**(`ANSWERSHEET_DATA_QUEUE`)异步判分入库。
- **局限**:防刷新丢答案,但换浏览器、清缓存、跨设备即丢;服务端在交卷前对作答进度完全无感知,无法做服务端接管。
- **证据**:`portal/src/main/webapp/resources/js/paper-examing.js`(saveAnswerSheet / loadAnswerSheet)、`portal/src/main/java/com/examstack/portal/controller/action/ExamAction.java:89-106`。

#### 6. java-exam —— HttpSession 会话内续答

- **机制**:作答中答案暂存服务端 **HttpSession**(`EXAM_ANSWER`、`EXAM_SUBMITTED_ANSWER`、`EXAM_QUESTION_ID_MAP`),同一会话内刷新或返回考试页可回填已选答案;剩余时间按 DB 记录的 `examStartTime` 服务端计算(`scheduledTime - (now - startTime)`),跨刷新持续扣时,防止重进重置计时。
- **交卷**:确认页点"正式交卷"后 `ExamHandInAction` 从 session 取答案一次性写 MySQL(`examquestionanswer` 表);`studentexamscore.examPhase` 仅"试卷初始化 / 最终得分"两态,阻止重复交卷。
- **局限**:会话过期、换设备、服务重启即丢;逐题保存无事务包裹、无幂等键;无定时保存请求。
- **证据**:`src/main/java/cn/lynu/lyq/java_exam/actions/ExamDetailShowAction2.java`(续答回填 + 剩余时间计算)、`actions/ExamHandInAction.java`(session → DB)。

## 五、与 EkuExam Cloud 的对照

| 维度 | Moodle | sg-exam | EkuExam Cloud |
|------|--------|---------|---------------|
| 定时快照 | ✅ 默认 60s | ❌ | ✅ |
| 动作驱动保存 | ❌(仅定时) | ✅ 切题 | ✅ |
| 幂等保障 | question usage 天然幂等 | (record, subject) 唯一索引 upsert | 快照版本号 / 去重 |
| 断点续答 | ✅ 从 DB 恢复 | ✅ 复用未提交记录 | ✅ |
| 客户端租约 | ❌ | ❌ | ✅ |
| 服务端超时接管 | ❌ | ❌ | ✅ |
| 持久化介质 | MySQL | MySQL | Redis(+ DB / Outbox) |

核心观察:

1. **服务端快照是少数派**:10 个项目中只有 4 个把考试中的答案落到服务端持久化存储;中文开源生态主流甚至允许"刷新即丢"。
2. **定时自动保存没有中文先例**:Moodle 是唯一的定时方案(60s 周期),其余服务端快照项目全部依赖"切题"这一用户动作触发——两次切题之间的作答在崩溃场景下必然丢失。
3. **没有人做租约与接管**:所有项目在考生断线后都只能"被动等待考生回来",不存在服务端主动接管交卷的语义;这正是 EkuExam Cloud 超时交卷机制的差异化价值。
4. **可借鉴的两点**:
   - sg-exam 的 **(record, subject) 唯一索引 upsert** 是最轻量的快照幂等实现,可作为对照基线检视本项目快照去重逻辑;
   - Moodle 的 **autosave 周期可配置 + 保存事件(attempt_autosaved)** 设计,便于运维按考试规模调节快照频率,其"保存事件"也对审计 / 监控有参考价值。
