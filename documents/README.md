## 与部署目录的边界

- 本目录维护业务原理、流程、调研和验收叙述。
- 部署操作继续维护在 `deploy/runbooks/`，参见 [超时交卷运维](../deploy/runbooks/TIMEOUT_SUBMISSION_OPERATIONS.md)、[Outbox 运维](../deploy/runbooks/OUTBOX_OPERATIONS.md)和[快照刷盘运维](../deploy/runbooks/SNAPSHOT_FLUSH_OPERATIONS.md)。
- 压测脚本、执行方式与原始证据继续由 [deploy/load-test](../deploy/load-test/README.md) 管理，不在本目录复制。报告中的 `deploy/load-test/results/` 证据属于本地忽略内容，新的克隆不一定具备。

## 维护约定

1. 技术文档使用稳定文件名，正文记录核对日期、适用模块、代码版本及工作区差异；避免以“最新版”作为版本依据。
2. 验收报告优先使用 `YYYY-MM-DD-主题.md`。只有正文能确认日期时才补日期，不根据文件修改时间推断。
3. 修订历史结论时保留原始证据，新增勘误，并在原报告顶部和验收导航中建立双向关联。
4. 技术事实集中维护在技术文档；面试稿引用技术依据，原始对话不作为当前实现的权威说明。
5. 移动文件时同步修复相对链接和仓库路径引用；不将机器绝对路径写入新的公共文档。

## 本地材料

`_local/` 整体由 Git 忽略，存放个人求职资料、毕业材料、环境记录、数据备份和生成产物；仅在原本具有这些材料的本地工作区存在。公共导航不依赖这些文件。

- `个人求职资料/`：个人简历、特定岗位备书和待审阅的专题笔记。
- `毕业材料/`：论文、答辩、参考范文；制作工程保留内部目录布局。
- `generated/`：独立的页面渲染目录；制作工程内的导出及预览仍随工程保存。
- `环境记录/`、`数据备份/`：本地排障记录、旧测试记录和数据库备份。

原 `docs/` 已归入 `_local/`。不要通过强制添加忽略文件将个人资料、备份或渲染产物纳入仓库。
